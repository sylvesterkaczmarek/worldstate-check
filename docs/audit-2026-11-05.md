# Verification integrity audit

## Scope

WorldState Check 0.2.0rc1 is an unpublished candidate. The audit began at commit
d2af56c. The original suite passed 136 tests. Twenty-seven new synthetic cases
reproduced failures before implementation; the unchanged original probes and
failure logs are retained in the local review handoff. The committed regression
file preserves those assertions. This pass is implementation, not independent
release approval.

## Findings and corrections

| Area | Reproduced behaviour | Correction |
| --- | --- | --- |
| API permission controls | Strings such as false and integer 1 were accepted as truthy permission opt-ins. | Require actual booleans before the engine can evaluate evidence. |
| Input validation | Unhashable check/operator/source types and excessive nesting escaped as Python exceptions. | Validate types and bounded JSON-compatible structure before dispatch; reject unused operator arguments. |
| Changing observations | Two checks could read contradictory versions of the same file and jointly verify. | Capture the file once per attempt, share its bytes across check types and reacquire on the next attempt. |
| Mutable specification | Caller changes during execution could change later assertions. | Evaluate an independently owned, validated specification snapshot. |
| TCP absence | DNS, timeout or local permission errors could satisfy reachable false. | Return UNKNOWN for inconclusive transport failures; explicit connection refusal remains a negative observation. |
| Output collision | CLI report output could overwrite the specification or evidence it just checked. | Preflight direct, resolved and hardlink collisions before evaluation, and check again before atomic replacement. |
| Saved reports | A recomputed checksum could validate arbitrary objects or inconsistent verdict/count fields. | Recompute structural counts and verdict, validate schema and metadata, and verify the digest. |
| File assertions | An unreadable content assertion hid a definite existence failure; hashing ignored its read limit. | Retain failure precedence and apply the same bounded snapshot to text and digest assertions. |
| CSV integrity | A ragged earlier row could be silently discarded before the final row was evaluated. | Require complete rows and strict CSV parsing. |
| Empty evaluations | The internal empty-results helper returned VERIFIED. | Return UNCERTAIN without required observations. |

Additional tests cover descriptor-relative parent replacement, optional-check
semantics, source hashes, fresh retries, malformed reports, preservation on failed
report writes, command output growth and owned descendant cleanup.

## Observation contract

Local file, JSON and telemetry checks share bytes for the same resolved pathname
within one attempt. The engine resolves these paths before dispatch and records
source SHA-256, size and observation time when bytes are read. Each assertion still
has its own size limit. Total retained file content is limited to 64 MiB per attempt.
A later retry has a new session and observes the current state again.

This prevents mixing incompatible versions of one artifact. It does not establish
an atomic snapshot across different files, HTTP responses, TCP connections or
commands, or prove that state remains unchanged after observation. Files changed
during a read are rejected when identity, size or timestamps reveal the change.
Those checks are detection heuristics, not adversarial filesystem attestation.

POSIX reads use directory-relative descriptors and reject replacement symlinks,
special files and multiply linked content files. Initial symlinks resolving inside
the authorized root remain supported. Platforms without equivalent directory APIs
use best-effort checks; concurrent path replacement is not a hardened Windows
sandbox boundary. Commands are trusted opt-in operations, not sandboxed workloads.

## Compatibility

Public API function names, keyword defaults, verdict names and CLI commands remain.
New reports add specification_sha256; legacy schema-1 reports without that field
can still pass structural and checksum verification. Metadata is additive, but
invalid or inconsistent legacy reports now fail verification.

Maximum explicit read and capture limits are 64 MiB. Freshness evidence retains the unrounded age used by its comparison, so an age
just outside a limit is not printed as exactly inside it. File digest-only checks now
use max_read_bytes, with the file default of 1 MiB. Increase the declared bound for
larger trusted files. Special files and multiply linked content are rejected.

Unused comparison fields are invalid rather than silently ignored. API permission
flags require True or False. CSV ragged rows are not accepted. A failed TCP name
lookup, local permission check or timeout cannot prove endpoint absence. Explicit
connection refusal retains ordinary reachable/unreachable comparison semantics.

Existing numeric comparisons retain exact integer behaviour and the represented
binary-float tolerance contract. HTTP checks retain their documented request-
completion failure semantics. Command timeouts remain failures of the bounded
command postcondition; capture overflow remains UNKNOWN.

## Evidence limits

The report SHA-256 is an unkeyed consistency check. Anyone who can rewrite a report
can compute a new checksum for a different internally consistent report. The
specification fingerprint identifies the evaluated specification but does not
authenticate the observer, prove causality, prevent replay or certify a sensor.
Freshness is evaluated only where a metric explicitly declares max_age_seconds.

The wait option budgets retries rather than preempting the entire in-progress
check. Individual network/command timeouts still apply. DNS and slow-stream I/O
are not claimed to obey a hard end-to-end real-time deadline. Process output uses
bounded retained buffers and monitored spool files; spool growth can overshoot
between polls and is not a hard disk quota. Detached Windows children retain
best-effort cleanup limitations.
